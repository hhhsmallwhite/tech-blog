## 1. 决策原则

1. **可逆性优先**：能低成本改的选择选最简单的；只在难逆的决策上投入思考成本。
2. **最小活动部件**：常驻服务、运行时、构建链越少越好；单人维护的项目，故障面比技术先进性更重要。
3. **学习价值让位于上线成功率**：学习诉求是加分项，不能用来掩盖自研认证/后台、额外运行时或静态发布延迟的真实成本。
4. **硬门槛一票否决**：不满足“单机 99 ECS 可运行、SEO、立即发布、单管理员、低维护”的方案直接出局，不用加权总分掩盖硬伤。

## 2. 逐项决策

### ADR-01 后端：Django 5.2 LTS

**背景**：单作者博客 + 公开站 + 单管理员后台，需要认证、会话、CSRF、后台 CRUD、ORM、迁移、模板。部署在 2C2G 单机，单人维护。

**决策**：Django 5.2 LTS（实施时锁 5.2.x 精确版本）。

**理由**：
- 项目中最容易写错、最耗工时的部分（认证、会话、CSRF、密码哈希、后台 CRUD、迁移、模板转义、部署检查）恰好是 Django 的内置能力，自研这些是纯风险。
- 服务端渲染天然满足“发布后立即生效”与 SEO，无需额外构建链。
- 5.2 为 LTS，支持到 2028-04，升级到 6.2 LTS 路径明确；长期维护成本可预期。
- 与求职方向一致：国内 Python 后端岗位对 Django 认知度高，面试可深入讨论 ORM、迁移、认证、部署与版本策略。

**正面后果**：后台开发量从 2000 行量级降到数百行定制；安全基线由框架提供；单一代码库、单一部署单元。

**负面后果（接受）**：
- 前端体验不如 React 生态，复杂交互需 HTMX/Alpine 或后续迁移。
- Django Admin 不是面向公众的产品界面，公开站必须自定义模板。
- 不能直接展示 FastAPI/React/TS 技能——这是有意识的取舍，不是遗漏。

**复审触发条件**：需要多用户/评论/协作；需要对外提供 JSON API 供第三方消费；或求职目标明确转向 FastAPI/全栈。

### ADR-02 公开站渲染：Django 模板 + HTMX + Alpine

**背景**：需求 AC-16/AC-19 要求保存后立即生效、无需改代码或重新部署；3M 带宽下首屏资源需克制；需 SEO。

**决策**：Django 模板为主；HTMX 与 Alpine 按页面需要引入，非强制。

**理由**：
- 服务端渲染直接满足“立即生效”，无构建/部署延迟。
- HTML-first，首屏不依赖 JS 执行，SEO 与 3M 带宽均友好。
- 无独立前端构建链、无 hydration，减少一个运行时与一套依赖。

**正面后果**：发布即生效；首屏 HTML/CSS/JS 可控在 500KB 内；无 Node 构建。

**负面后果（接受）**：模板层易重复，需用 include/模板标签保持结构；HTMX 交互只能靠 Playwright 测，无法纯单元测试。

**复审触发条件**：公开站出现大量客户端状态或富交互；或需要离线能力。

### ADR-03 数据库：SQLite 3.54（WAL）

**背景**：单作者写、访客读，写事务短且少；单机部署；需备份可恢复。

**决策**：SQLite 3.54.x，启用 WAL、`busy_timeout`、外键约束；只运行一个应用容器。

**理由**：
- 写入只来自一个管理员，单写者队列完全够用；SQLite 官方 *When To Use* 明确此类场景合适。
- 无独立服务，几乎不占额外内存；备份是文件级操作，恢复路径可演练。
- Django 官方推荐 PostgreSQL 属通用建议，不构成本项目写并发的硬性要求。

**必须配置**：WAL、`busy_timeout`、外键约束、合理 `synchronous`；**不得放在 NFS/网络文件系统**；多 worker 可共享同一文件（写会串行）。

**备份规范**：使用 SQLite 在线备份 API 或 `VACUUM INTO` 生成一致性快照；**禁止在高写入时直接 `cp` 数据库文件**。

**负面后果（接受）**：单机上限；多实例/多容器同时写不合适；复杂并发事务、行级锁、物化视图、PostGIS 等能力缺失。

**复审触发条件**：需要多实例部署；出现多写并发（多用户/评论/协作）；需要 PostGIS 或复杂分析查询；或明确以学习 PostgreSQL 为目标。迁移成本：中等（Django ORM + 数据导出导入 + 连接配置切换）。

### ADR-04 后台：Django Admin + ModelAdmin

**背景**：单管理员，需要文章/项目/关于页 CRUD、草稿/发布/撤回、删除确认、图片上传、Markdown 编辑。

**决策**：Django Admin 作为后台主体，通过 ModelAdmin 定制；不引入独立 SPA 后台。

**理由**：Admin 白送模型级 CRUD、列表筛选、搜索、批量操作、删除确认、权限校验；自建同等功能是 2000 行起步，且安全代码量显著增加。本质交易是“接受后台界面简陋，换掉 80% 的后台代码”。

**需要额外开发的部分（已识别，非白送）**：
1. Markdown 编辑器控件与“上传后插入光标位置”——整个后台最费劲的一块，需 EasyMDE/CodeMirror + 少量 JS。
2. 发布/撤回 Admin action、预览视图、`body_text` 生成——约 100～200 行。
3. 图片上传字段与类型/大小校验（禁 SVG）。
4. 登录失败锁定（django-axes）。

**负面后果（接受）**：后台 UI 不可定制到产品级；公开站必须另写模板，不能把 Admin 当前台。

**复审触发条件**：后台视觉/交互成为作品集重点；或需要 Admin 无法表达的业务流程。

### ADR-05 密码修改：启用

**背景**：需求 Q-06 原默认“首版不提供”，忘记密码走服务器侧运维重置。

### ADR-06 域名与 ICP：延期，双阶段上线

**背景**：大陆服务器绑定域名必须完成 ICP 备案（免费，通常 1～3 周）。当前决策为**不着急**，即不把备案作为首版交付的阻塞项。

**决策**：采用双阶段方案，备案与开发解耦、并行推进。

**阶段 A —— 无域名开发与验收（现在～决定公开前）**
- 本地开发 + ECS 上以 **IP + HTTP** 部署，用于功能验收与 CI/CD 打通。
- **后台绝不长期暴露在公网 HTTP**：通过 SSH 隧道访问（`ssh -L 8000:127.0.0.1:8000`），或安全组仅放行本人 IP；公开站端口可开放，后台路径另加限制。
- 站点绝对 URL 用环境变量 `SITE_URL` 占位（如 `http://<ECS-IP>`），canonical/sitemap/分享卡片均从该变量生成，避免硬编码。
- SEO 相关验收（AC-27～AC-29）在阶段 A 只能做**结构正确性**验证（标签存在、sitemap 格式合法、robots 可访问、404 状态码正确），**不做**搜索引擎实际收录验证。

**阶段 B —— 决定公开时**
- 购买域名 → 提交 ICP 备案 → 备案通过后解析 → Caddy 自动申请 HTTPS → 切换 `SITE_URL` 为正式域名。
- 切换后复核 AC-27～AC-29，并提交 sitemap 到搜索引擎。

**风险与缓解**：
- 风险：`SITE_URL` 切换遗漏导致 canonical/sitemap 指向旧地址。缓解：集中配置单点、切换后跑一次 E2E 断言页面 canonical 与 sitemap 域名。
- 风险：阶段 A 后台暴露。缓解：SSH 隧道 + 安全组白名单 + 不在公网 HTTP 上长期登录。
- 风险：备案耗时超预期影响上线。缓解：阶段 A 不依赖备案，随时可停可续。

**复审触发条件**：决定正式公开上线时，立即启动阶段 B。

### ADR-07 代码仓库与 CI：公开 GitHub + Actions

**决策**：公开 GitHub 仓库；GitHub Actions 作为 CI/CD。

**理由**：公有仓库 standard runner 免费且不限分钟；招聘者可直接看到代码、提交历史与 CI 徽章，对作品集是加分项。私有仓库 Free 档 2,000 分钟/月对本项目也够用，因此若中途需转私有，成本低。

**补充约束**：
- 第三方 Actions 按 commit SHA 固定，避免供应链风险。
- Secrets（SSH 私钥、服务器指纹、环境变量）放 GitHub Secrets，不入库。
- 部署用户非 root，仅授权必要目录与 Docker 命令。

**负面后果（接受）**：大陆访问 GitHub 可能抖动，需 pip/阿里云镜像与 Docker 镜像加速；私有代码不可用（本项目无此需求）。

### ADR-08 备份与监控：最小化

**决策**：
- 备份：阿里云文件备份（99 套餐含 100GiB 权益）覆盖 `/srv/blog/data` 与 `/srv/blog/media`；每日 `sqlite3 .backup` 或 `VACUUM INTO` 生成一致性快照，保留 7～30 天。
- 监控：`/healthz`（应用进程 + 数据库可读 + 磁盘余量）+ 外部 uptime 探测 + Docker `restart: unless-stopped` + 日志轮转；告警到邮箱。
- **不引入** Prometheus/Grafana/Sentry（首版）。

**核心原则**：**未演练过的备份等于没有备份。** 每月至少一次恢复演练（临时目录恢复数据库与媒体 → 启动应用 → 验证文章/图片/关于页），优先级高于扩充备份方案。

**复审触发条件**：需要异地副本（加 OSS）；或线上出现难以定位的异常（加 Sentry 免费档）。

---

### ADR-09 站内搜索：`icontains`

**决策**：首版用 `icontains` 匹配标题、摘要与 `body_text`（保存文章时去除 Markdown 标记后落库，避免每次查询解析 Markdown）；拉丁字母大小写不敏感。

**理由**：数据量为个人博客量级，全表扫描在毫秒级；无需索引维护、无需额外常驻服务。不引入 Meilisearch/Elasticsearch。

**负面后果（接受）**：无相关性排序；数据量增长后变慢。

**复审触发条件**：文章超过约 1000 篇，或搜索质量成为关键体验 → 升级 SQLite FTS5 + 中文分词（jieba），需要额外 FTS 表与同步逻辑。
