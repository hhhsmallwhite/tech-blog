## 2. 开发阶段与整体顺序

**为什么是这个顺序**：先冻结接口与数据地基（M0～M1），再建跨域共享服务并最早验证最大技术风险（M2），然后按"访客侧→作者侧→质量收口→部署"推进（M3～M6）；生产部署永远排在全部自动化测试与安全检查之后（原则落实见 task-breakdown §3.5）。

| 里程碑 | 主题 | 任务 | 出口条件 | 阶段门（用户参与点） |
|---|---|---|---|---|
| M0 | 仓库与骨架 | T-001～T-004 | 空项目可跑，CI 骨架绿 | M0 完成汇报确认 |
| M1 | 领域模型 | T-005～T-010 | 模型不变量 L1 全绿，迁移门禁入 CI | M1 完成汇报确认 |
| M2 | core 服务+风险验证 | T-011～T-016 | XSS/上传/healthz 测试全绿，编辑器风险出结论 | M2 完成汇报确认 |
| M3 | 公开站点 | T-017～T-022 | 公开页全部 AC 的 L2 通过 | M3 完成汇报确认 |
| M4 | 后台 Admin | T-023～T-028 | 后台全部 AC 的 L2 通过 | M4 完成汇报确认 |
| M5 | 质量收口 | T-029～T-032 | main 六门禁绿（第六道启用点 T-033） | M5 完成汇报确认 |
| M6 | 阶段 A 部署 | T-033～T-039 | ECS 上 IP+HTTP 可访问，tag 自动部署演示一次，首轮备份演练完成 | 部署授权（红线 R10）+ 阶段 A 验收确认 |
| M7 | 阶段 B（未来） | T-040～T-041 | 条件触发，不排期 | U-5 用户决定公开 |

阶段门规则：每里程碑完成必须向用户汇报出口条件（附证据链接）并获确认后才进入下一里程碑；红线操作（`development-workflow.md` §9）任何时刻需用户亲口授权。

## 3. 范围三区

**第一版必须（T-001～T-039）**：任务明细见 `task-breakdown.md` §4～§10。

**可选增强（不排期；触发即按可选增强流程评审排期）**：

| 增强 | 触发条件 | 留缝位置 |
|---|---|---|
| RSS/Atom | 读者需求 | 复用 published()，加 feed 视图 |
| FTS5 全文搜索 | 文章>1000 篇或搜索质量痛点 | search_articles 单点替换（ADR-09） |
| 渲染缓存 | TTFB 可感知上升 | 渲染函数加装饰器（AD-3） |
| 媒体库/OSS | 图片管理需求 | core.uploads 接口不变 |
| PostgreSQL | 多实例/写并发/学习目标 | 全 ORM 零改动切换（ADR-03） |
| 评论/多作者/CDN | 产品决策 | 模板区块位/auth 扩展/URL 可配 |
| 2FA/严格 CSP/Argon2/病毒扫描/Sentry/request-id/集中日志/webhook | 安全与运维升级窗口 | security/deployment 延后列 |
| mypy + django-stubs | 上线稳定后独立 PR（决策修正 #3；DoD §4 不适用声明的解除） | CI 预留扩展 |
| Vitest 前端组件层 | 自定义 JS 成规模 | TST-1 |

**未来规划（条件触发）**：T-040～T-041 阶段 B（域名、备案、HTTPS 切换，ADR-06）。

## 7. 计划决策 PLN-1～PLN-10

| # | 决策 | 依据 | 替代（不选原因） |
|---|---|---|---|
| PLN-1 | 一任务一 PR，文件白名单制 | 评审有效、回滚容易 | 大 PR |
| PLN-2 | 依赖序：模型→core→公开→后台→质量→部署；spike 前置 M2 | 接口先冻结、风险前置 | 按页面纵切 |
| PLN-3 | S/M/L 相对估算+类型依据 | 单人+Agent 节奏不定 | 人时（虚假精度） |
| PLN-4 | L1/L2 随任务 TDD，L3 在 M5 收口 | 定位成本 | 全 E2E 后置 |
| PLN-5 | M7 列出不排期 | ADR-06 解耦 | 一体排期 |
| PLN-6 | 任务内"失败测试→实现→通过→提交"微循环 | 小步可验证 | 大块后补测试 |
| PLN-7 | docker build 门禁启用点=T-033 | 构建能力就绪即闭环；生产部署仍在全部检查后 | 提前放 M5（无 Dockerfile） |
| PLN-8 | 热点文件串行合并+rebase | 消除并行冲突 | 自由并行 |
| PLN-9 | **验证证据规则：完成判定唯一依据=PR 验证记录；未执行不得勾选** | 用户第二轮审查要求 7 | 口头/记忆声称（不可追溯） |
| PLN-10 | **三场景强制：验收标准=预期行为+正常/边界/失败；契约断言=状态码+内容+适用头** | 用户第二轮审查要求 1/2 与反模式 1/2/3 | 自由格式验收（易漏边界） |
